Two things to read carefully. First, the harness does **not** withdraw the Phase-1 tools after the lock (`toolbox.specs()` is computed once per run), so "nav tool called again" counts the model going back to search, not the harness refusing it - a phase-gating implementation would turn that number into refusals. Second, a negative reduction means the lock happened so early that the rebuilt Phase-2 context was *bigger* than the short history it replaced; compaction is not free, and triggering it on turn 3 is not the same mechanism as triggering it on turn 13. The compacted-vs-never-compacted patch line is confounded for the same reason a lock is a model action: the 9 runs that never compacted are the runs that never produced a valid `lock_targets`, so the line mixes the mechanism with the model's ability to enter it.

## Caveats

- **Resolved Rate is empty on purpose.** It needs the SWE-bench Docker evaluator (Bước 5), which has not run; nothing here guesses it. Valid Patch Rate is the measured upper bound: a non-empty diff is not a correct fix.
- **M1's numbers are partly a request-shape artefact.** Under M1's structured edit schema + `_EDIT_STRUCTURED` prompt, E2B writes `search_text` arguments as `pattern="x"\npath` with Gemma 4 template tokens inside them (9 of 50 cells, 83 calls; no B0/M2/M3 cell does this at temperature 0). Those are scored as `JSON_SCHEMA_ERROR`, which is why M1 leads that column - they are evidence against M1 as specified, not about the syntax gate (`AST_SYNTAX_REJECTED` measures that).
- **`>16K` holds very few calls.** Anything read from that row is an anecdote; `figures/metric4_e2b.png` prints the denominators for the same reason.
- **Compaction text is not in the trace.** `harness/agent.py` logs the compaction's sizes, locked files/symbols and the root-cause note, not the reconstructed messages; recovering the text would require replaying `compact_messages` against the worktree. (Traces written after 2026-10-21 also log `compacted_prompt_preview`, so a run set without it predates that field.)
- **One trace per cell.** A cell that was re-run keeps only its newest scoreable trace, so the 50 tasks are counted once each, not once per attempt.
