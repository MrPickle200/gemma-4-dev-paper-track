## 2. Error taxonomy

Every failed call, per config. The harness has no shell: B0's bash tools are `search_text`/`read_file`/`list_dir`, so `BASH_EXECUTION_ERROR` means one of those returned `ok=False` (invalid regex, path not found) - the analogue of a non-zero exit code. `apply_edit` failures are split by cause, not by tool. Two things to read carefully. First, the harness does **not** withdraw the Phase-1 tools after the lock (`toolbox.specs()` is computed once per run), so "nav tool called again" counts the model going back to search, not the harness refusing it - a phase-gating implementation would turn that number into refusals. Second, a negative reduction means the lock happened so early that the rebuilt Phase-2 context was *bigger* than the short history it replaced; compaction is not free, and triggering it on turn 3 is not the same mechanism as triggering it on turn 13. The compacted-vs-never-compacted patch line is confounded for the same reason a lock is a model action: the 9 runs that never compacted are the runs that never produced a valid `lock_targets`, so the line mixes the mechanism with the model's ability to enter it.

## Caveats

- **Resolved Rate is empty on purpose.** It needs the SWE-bench Docker evaluator (Bước 5), which has not run; nothing here guesses it. Valid Patch Rate is the measured upper bound: a non-empty diff is not a correct fix.
- **The M1 request-shape defect did not occur in this run set.** No call was scored `JSON_SCHEMA_ERROR`, i.e. no argument key glued two parameters together. The schema now carries `additionalProperties: false` and the harness repairs a glued key with a regex fallback (TASK.md Task 2), so this is the expected result of the fix - and a regression here means one of the two stopped working.
- **`>16K` holds very few calls.** Anything read from that row is an anecdote; `figures/metric4_e2b.png` prints the denominators for the same reason.
- **Compaction text is in the trace.** Each `compaction` record carries the full Phase-2 message body under `compacted_prompt_preview`, plus the directive and the size of the locked source, so the rebuilt context can be read without replaying `compact_messages` against a deleted worktree.
- **One trace per cell.** A cell that was re-run keeps only its newest scoreable trace, so the 50 tasks are counted once each, not once per attempt.
